# AI 生产的测量、路由与复盘：让导演方法可复现、可算账、可迭代

> 上一份 `ai-video-platform-production.md` 解决"怎么把镜头做出来"；本文件解决"怎么稳定地、省成本地、可追溯地批量做出来并越做越好"。
> **个人/小团队轻量优先**：不要求数据库、API、对象存储或专职团队。下列模板一个 Markdown 表 + 统一命名就能跑；团队化后再升级工具。核心是养成"留记录、按数据决策、熔断止损、复盘迭代"的习惯，而非堆流程。

## 1. 导演 Shot Spec 与平台 Prompt 适配器分离（防单平台过拟合）

把每镜的产出拆成两层，分开存档：

- **导演 Shot Spec（模型无关母版）**：就是七层核心——摄影/运镜/灯光/色彩/表演/材质/声音 + 首末态、台词、口型级、切点、验收标准。换任何模型都不变。
- **平台 Prompt 适配器（随平台变）**：该平台吃整句还是关键词、负面词格式、时长/比例/参数、首帧怎么传、台词内嵌还是分轨。换平台只重写这一薄层。

不要把平台参数、积分、特定模型名焊进导演母版；模型一升级/换平台，母版仍可复用。

**每镜验收标准要可判定**，写进 Shot Spec，例如："角色脸型不漂移；右手持按钮；该动作全片只执行一次；末帧人物站位可接下一镜；A+ 镜口型对上。"QC 按它判过/废，不凭感觉。

## 2. 轻量生成日志（零成本，算出钱花在哪）

> 单镜头的完整可复现档案（意图/控制信号/输入资产版本/prompt/take/失败史）用 **Generation Recipe**（见 `generation-engine.md` 第9节）；本日志是跨镜汇总与成本统计，Recipe 是镜头级明细，二者配合，Asset Bible 管资产版本。

每生成一条记一行（批量时边做边记，别事后补）：

| ShotID | 镜型 | 模型/版本 | 首帧资产 | Prompt版本 | 第几条 | 结果(过/废/待定) | 缺陷编号 | 备注 |
|---|---|---|---|---|---|---|---|---|
| SH-007 | 对白正脸 | 模型X/vN | CHAR-02 | p3 | 1 | 废 | D3 | 停顿没出来 |
| SH-007 | 对白正脸 | 模型X/vN | CHAR-02 | p3 | 2 | 过 | — | 留 |

**镜型分类**（用于路由，见第4节）：①静态表演 ②对白正脸 ③多人交互 ④动作/走位 ⑤复杂运镜 ⑥VFX/奇观 ⑦空镜/UI/后期。

从日志能直接算（个人也该每月算一次）：
- **首轮可用率** = 一次过的镜数 ÷ 总镜数；
- **每通过镜重生次数** = 总生成条数 ÷ 通过镜数；
- **缺陷 Pareto**：按缺陷编号统计，前 2–3 类就是最该解决的（往往 80% 废镜来自 2–3 类问题）；
- **可用秒成本** = 总积分（或钱）÷ 最终可用镜头秒数——这是跨平台/跨项目真正可比的成本指标。

## 3. 缺陷分类 Taxonomy（与 checklist G6 对应，日志填编号）

| 编号 | 缺陷 | 首选对策（单变量改，别一次改多处） |
|---|---|---|
| D1 | 身份漂移（脸/发/服装/标志物变） | 锁定定妆照首帧；简化背景；同角色集中一批生成 |
| D2 | 肢体/手指/多肢/融合 | 减少手部动作；用道具/景别遮挡；拆成特写+中景 |
| D3 | 口型/台词（错位、诡异、多话、说话者错） | 降口型级（A+→用侧脸/反应镜）；台词分轨；缩短单句 |
| D4 | 运镜（乱晃、无理由推拉变焦） | 明确写"固定"；删掉多余运镜词；换更听话的模型 |
| D5 | 文字乱码/UI/水印 | 可读内容全部转后期，画面只留占位发光块 |
| D6 | 动作衔接（重演、相位断、方向反、越轴） | 用上镜尾帧当首帧；复述末态；锁屏幕方向/轴线 |
| D7 | 光色跳变（相邻镜色温/曝光/肤色突变） | 统一光向色温描述；同场景同批；后期镜头匹配 |
| D8 | 单段超载（一段要互动+口型+运镜+VFX） | 拆 Shot，降低一段内同时任务数 |
| D9 | 主体融化/拖影/撕裂/帧闪 | 降低运动幅度与速度；缩短时长；换模型 |
| D10 | 道具/人数/数量穿帮 | 首帧固定道具与人数；群像用 2–5 前景 + 背景 |

## 4. 熔断与重生规则（直接省积分）

> 与 `solo-workflow.md` 第7节"两次/三次规则"配套：第1次单变量改词 → 第2次降负荷/拆镜/降级 → 第3次换 Generation Route（控制方式）或模型 → 仍不行回 Cut Map 改戏。下列是积分侧硬阈值。

- **单镜熔断阈值**：同一镜同方案连续 **3 条**不过 → 停，不硬烧。按顺序换策略：①单变量改 prompt（对照第3节对策）→ ②降负荷/拆镜 → ③降口型级或换遮挡构图（B 级）→ ④换生成路线（控制方式，见 v11 Route 矩阵）或换模型 → ⑤改为后期/剪辑规避。
- **A+ 镜例外但有上限**：关键镜可多生成备选，但也设上限（如 5–6 条）；仍不过说明该镜设计超模型能力，回 Cut Map 改拍法，不无限重试。
- **C 级镜"挑能用就过"**：画外系统声、群杂、空镜、UI，不追求完美，不为它烧重生。
- 每次熔断在日志备注写下"最后怎么解决的"，沉淀成你自己的对策库。

## 5. 镜型 → 模型路由（小规模实测，不押万能模型）

> 注意区分两层路由：**Generation Route（v11 第6节）决定"用什么控制方式"**（T2V/I2V/首尾帧/V2V/多图/分轨/后期）；**本节决定"同一控制方式下用哪个模型引擎"**。先定 Route，再按镜型选模型。

不同模型在不同镜型上强弱不同（对白口型、动作、多人、运镜、VFX 各有所长）。

- **代表镜基准（轻量版）**：从片里挑 **5–6 个覆盖主要镜型的代表镜**（不必30镜），用手头 2–3 个模型各跑一遍，按日志记录谁在哪类镜型过、主缺陷是什么，得到一张**路由表 v1**：

| 镜型 | 首选模型 | 备选 | 已知坑 |
|---|---|---|---|
| 对白正脸/口型 | 实测填 | | |
| 多人交互 | | | |
| 动作/走位 | | | |
| 复杂运镜 | | | |
| VFX/奇观 | | | |

- 之后按镜型路由生成；某模型在某镜型连续熔断，临时切备选并更新路由表。
- **回归集**：固定这 5–6 个代表镜长期保留。模型每次大升级，先重跑回归集对比，确认脸/风格/口型没漂移再用于正式镜头——模型升级常悄悄改变画风。
- 路由表、模型能力以你当期实测为准，不抄别人结论，不写死。

## 6. Asset Bible 轻量台账与版本锁

- 统一命名带版本：`CHAR-01_小乔_v2.jpg`、`SET-05_控制室_v1.jpg`、`SH-007_p3`（prompt 第3版）。改了就升版本号，不覆盖旧文件。
- 一张资产表：

| AssetID | 类型(角色/场景/道具) | 版本 | 文件名 | 关联Shot | 来源/授权 | 更新 | 备注 |
|---|---|---|---|---|---|---|---|
- 定妆照/场景图先锁定再生视频；某角色脸中途要改，升版本并明确"从哪个 Shot 起换新版"，避免半片新脸半片旧脸。
- 记录参考图来源与授权（自拍/可商用/AI生成/他人作品），肖像、声音、品牌 Logo 尤其注意。

## 7. 个人版审批 Gate（一人分饰多角，靠切换视角验收）

独立制作没有团队，但在每个 Gate **切换验收帽子**：导演（叙事对不对）→ AI TD（模型/参数/成本）→ 连续性/资产（脸和道具有没有漂）→ 剪辑/声音（节奏声画）→ QA（按验收标准判过废）。

`意图/分镜锁定 → 资产锁定 → 代表测试镜通过 → 按批次生成（日志+熔断）→ 终剪/声画 → 盲测 → 发布 → 复盘`

- 没锁资产不批量；代表镜没不过不批量（用户明确跳过测试片时，至少先验证平台未用过的新能力）。
- 保留 **10%–20% 实验镜**配额：允许少量镜头偏离标准模板做风格/手法探索，成了用、不成就回标准版，防止全片被"安全模板"磨得趋同。

## 8. 观众盲测（轻量）与复盘

- **盲测**：终剪后找 **2–3 个没看过剧本的人**看一遍，只问三句：①这片子讲了什么？②谁做了什么、结局怎样？③哪里没看懂/出戏？据此算粗理解率、找出戏点。导演自己觉得清楚 ≠ 观众看懂。
- **发布后复盘（Postmortem）**：用日志数据回看——首轮可用率、平均重生次数、缺陷 Pareto、可用秒成本、哪类镜型最烧钱、哪个 G6 缺陷最多；把对策回填进本文件和路由表，下一部直接受益。
- 目标平台确定后再看平台数据（完播率、关键节点流失、互动）；此前不臆造指标。

## 9. AI 来源披露与可追溯交付

越来越多影展/平台/客户要求披露 AI 使用。全程留痕即可低成本满足：
- 每个镜头可追溯：用了哪个**模型名+版本**、**Prompt 版本**、首帧资产版本、生成日期、AI 参与范围（画面/配音/音乐/字幕）；
- 参考素材的来源与授权；人工做了哪些（剪辑/调色/声音/后期 UI）；
- 生成日志本身就是流程证据。交付或投稿前按目标方要求导出一份 AI 使用说明。

## 10. 个人可算的核心 KPI（目标值自测，不抄数字）

首轮可用镜头率、每通过镜重生次数、严重缺陷率（D1 身份 / D6 衔接）、可用秒成本、镜头生产周期 P50/P90、日志覆盖率、盲测剧情理解率。
**先跑出自己的真实基线再定改进目标**；任何"应达到 X%"在没有你自己数据前都是空话。
