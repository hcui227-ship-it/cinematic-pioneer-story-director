# 单人 AI 导演工作流：状态机、镜头契约、生成路由与失败循环

> 本文件解决"**一个人如何用生成结果持续做导演决策**"。
> 核心转变：①线性流程 → 可跳转状态机；②前置读全/写全 → 风险触发加载、最小有效提示词；③纸面完整 → 尽早粗剪、素材反推；④失败就堆词/拆镜 → 先判断生成路线是否错误。
> 本文件定义导演层机制；摄影/灯光/表演/声音等工艺细节在各自 reference，作为"被当前镜头风险触发的工具"，不前置全读。

> **镜头级生成机制统一见 `generation-engine.md`（镜头生成引擎）。** 本文件负责导演层：状态机 S0–S8、Hard/Soft/Open 锁、Probe、Cut Map、粗剪反推、单人工艺视角（第1–4、11、12节）；以下镜头级机制以引擎层为准：
> - 第5节 Shot Contract 需配套 **Control Map（MUST CONTROL/CAN DRIFT）**；
> - 第6节 Generation Route 以引擎层的 **控制信号分类 + Generation Router + 运动/空间代理** 为准；
> - 第7节两次/三次规则对应引擎层 **Accept / Repair / Reroute（含拆分控制链、不经济改戏）**；
> - 第8节最小有效提示词遵循"**把控制从 Prompt 拿出去、Prompt 是最后一公里**"；
> - 第10节连续性 L0–L3 已并入引擎层 **Control Budget L0–L3**（衔接敏感度成为定级因子之一）；
> - 镜头级完整可复现档案用 **Generation Recipe**。

## 0. 开场协议 Intake：从一句想法到开工对齐（S0 第一动作）

大多数用户不是导演，也不懂 Control Map、Proxy、PBR、Beat、Cut on action 这些词；他们给的常常是一句想法、一张参考图、或一段模糊的"我想要那种感觉"。**不要拿到想法就闷头写分镜/提示词**，先用一轮轻量沟通对齐，再进入状态机。开场只做三件事 + 一条语言规则。

### 0.1 三步开场

**① 回显（确认听懂）**：一两句复述——要做什么片、发在哪/什么形态、我听到的硬约束；并明确分栏：
- 【你给的事实】：用户明确说的剧情、台词、结局、参考、平台、时长、禁令；
- 【我先替你假设的】：用户没说、但开工需要的项，我先给默认并标注，他可否决。

**② 列路线（告诉他接下来做什么）**：给一张针对**这个项目**的开工清单，而不是泛泛流程。典型顺序：确认少数关键点 → 先做 1 个最便宜的探针验证最高风险 → 出角色/场景资产清单 → 列 Cut Map（不写提示词）→ 逐镜走生成引擎 → 攒一批就粗剪反推。每步标清：**这步我做什么 / 需要你给什么或拍板什么 / 你会拿到什么**，让用户始终知道进度与自己的动作。

**③ 精准反问（只问高杠杆问题）**：判定标准是"答案不同会不会导致方向性返工"，会才问；不问不影响交付的。一次最多 3–5 个，优先选择题/是非题并**附推荐答案**；用户答"你看着办/用默认"就立即走省心默认档（0.4），不卡住、不连环追问。

### 0.2 高杠杆澄清清单（按需挑，不必全问）

| 我要确认的 | 为什么影响成败 | 白话怎么问（不抛术语） | 可安全默认 |
|---|---|---|---|
| 现在要的是成片/视频，还是只要分镜脚本/提示词/方案 | 决定走不走生成引擎、要不要资产与配方 | "你是想直接拿到能去生成的镜头方案，还是先要一份剧本分镜？" | 要可落地的分镜 + 生成方案 |
| 发在哪、横竖屏、大概多长 | 画幅与时长决定镜头量、构图、口型密度 | "发抖音/视频号竖屏，还是 B 站/影展横屏？先做多长一支？" | 按用途建议画幅；先做 30–60 秒一支 |
| 有没有必须保留的剧本/台词/结局，可否原创补全 | 是 Hard 锁，决定能不能加人物/冲突/对白 | "故事和台词是一字不能改，还是可以在你这个梗概上帮你补全？" | 梗概即授权补人物冲突对白，关键事实不动 |
| 用什么生成平台/模型，支不支持图生视频、台词内嵌配音 | 决定台词内嵌还是声画分轨、参考图用法、成本 | "你手上是哪个 AI 视频工具？它能不能用参考图、能不能直接生成说话配音？" | 按"图生视频 + 台词内嵌"规划，口型能力先探针，以实测为准 |
| 有没有角色/场景参考图或素材、预算/时间上限 | 决定先做资产还是素材先行、控制预算档位 | "有现成的人物图、场景图或拍的素材吗？积分/时间大概什么上限？" | 没有就先出定妆/场景资产；成本有限则台词内嵌、空镜从简 |
| 风格/质感参照 | 决定摄影、材质、光色、动作强度 | "想贴近哪部片/哪种画面（给片名或图都行）？要游戏 CG 质感还是纪实真实感？" | 按题材给一个克制的风格提案，标为 Soft 锁可否决 |

### 0.3 术语说人话（对内专业，对外只谈效果）

> 全套术语的标准白话名/一句话解释统一查 [`plain-language-glossary.md`](plain-language-glossary.md)，以它为唯一权威，不在多处重复维护。给用户的步骤、模板、进度默认"白话名（专业名）"。

- **只问效果，不问术语**。不要让用户在 L0–L3、PBR、I2V 之间做选择；把每个专业选择翻译成他能凭直觉判断的画面问题：
  - 控制预算 → "这个镜头里，人物的脸、服装、动作有哪些是**必须一模一样、错了就穿帮**的？哪些背景细节随便一点没关系？"
  - 口型分级 → "这句台词是必须正脸清楚说出来，还是可以侧脸/背影/画外音？"
  - 运动代理 → "这个走位/运镜很复杂，我会先用一段粗制小动画/手机样片把动作和镜头定死，再让 AI 照着拍，可以吗？"
  - PBR/3A 材质 → "你要游戏 CG 那种金属反光、皮肤通透的精致质感，还是纪录片那种真实粗粝感？"
- **内部产物保留专业结构，对外配白话注解**。给用户看 Control Map 时附一句"这张表是逐个镜头定清楚：哪些东西必须锁死免得 AI 乱改脸/乱换道具，哪些可以让它自由发挥"；看 Recipe 时附"这是这个镜头的完整配方，方便换个 AI 也能重做、以及发布时说明用了什么"。
- 专业词第一次在对用户的话里出现时，紧跟一个可见效果解释（写"伦勃朗光"要补"脸颊一侧一块三角形亮斑、另一侧沉在阴影里"）；用户明显熟练（直接给剧本、自己会说术语）时少解释、直接走。

**用户白话 → 导演判断速查（听到这些话的默认动作）**：

| 用户说 | 通常意味着 | 默认做法 |
|---|---|---|
| "要高级/电影感" | 反感模板化、堆特效 | 克制运镜（情绪重的镜头固定）、大光比、有理由的少数运动、敢留静默 |
| "要爽/打击感/燃" | 动作戏要力度 | 运动代理锁走位、接触点插入镜、蓄力-爆发-收势、命中顿帧与冲击连锁（C 类，见 `toolbox-rendering-3a.md` 第 4 节） |
| "人物别变脸/别换衣服" | 身份连续性 HIGH | 定妆参考 + 同角色批量 + I2V 首帧 + 正脸镜多生成备选 |
| "要像游戏/3A 大片" | 要 PBR 写实质感 | 材质在定妆/道具静帧锁定（GI/AO/SSS、刃口高光），视频只写材质的受力/磨损/沾尘变化 |
| "便宜点/积分不够" | 控制成本 | 先资产后视频、空镜 L0 用 T2V、C 级挑能用、同方案 3 条不过即熔断、台词内嵌省一条配音 |
| "我不知道，你看着弄" | 授权走默认 | 走 0.4 省心默认档，只在 Hard 分歧和探针结论时回来确认 |

### 0.4 省心默认档（用户放手时直接采用，均为 Soft 锁、可随时改）

- 先做**一支 30–60 秒**的短片跑通，而不是一上来规划长片；画幅按发布平台（竖屏短视频 9:16 / 横屏短片 16:9）。
- 流程走"图生视频 + 台词内嵌配音"（成本有限时不单独做配音母版）；正脸口型、复杂运镜等未验证能力**先做探针**。
- 镜头以固定/小幅运动为主、运镜必须有叙事理由；所有可读中文/数字/招牌/字幕**后期合成**；风格给一个克制提案。
- 先出角色定妆与场景 establishing 图再开视频；同角色/场景集中一批生成保脸；空镜与画外声按 C 级"挑能用就过"。
- 采用前用一句话告诉用户"我先按这套默认开工，任何一项你都可以随时改"，把默认显式化而不是偷偷决定。

### 0.5 风险前置（开场就说，不等翻车）

在列路线时主动点出本片最高风险及对策，把 Probe 的理由提前讲清楚，例如："你要的多人同时抢话 + 精确口型，目前单条视频通常做不稳，我会先用一条 3 秒探针验证；不行就拆成两人各自的镜头再剪、系统提示音走画外，不影响成片效果。"让用户在开工前就知道哪里可能要改设计，而不是写到一半才发现。

### 0.6 两种开场范例

**新手一句话**："我想做个 AI 短片，讲一个外卖员发现自己困在时间循环里。"
> 回显：你想做一支叙事向 AI 短片，主角是外卖员、核心设定是时间循环；【事实】目前只有这一句；【我先假设】竖屏、约 45 秒、允许我补人物和对白、走图生视频+内嵌配音、偏写实电影感。
> 接下来我会：①和你确认下面 3 点 → ②先做 1 条探针验证"循环重复画面"这个最容易翻车的效果 → ③出外卖员定妆和 2–3 个场景图 → ④列镜头蓝图给你确认 → ⑤逐镜生成并粗剪。
> 只问 3 个：1）发竖屏还是横屏？（默认竖屏）2）结局想停在"他逃出来了"还是"开放式又一轮"？（默认开放式更有余味）3）有想用的 AI 视频工具吗？（没有我按通用图生视频规划）。其余我先按默认来，你随时可改。

**老手给剧本 + 平台**：用户直接发来完整剧本、指定平台与时长。
> 不回问基础项；只确认 Hard 锁（哪些台词/结局一字不能改）、跳过风格扫盲，并直接提出探针选镜："剧本里有两处同框多人抢话和一处一镜到底绕桌，我建议拿这镜做探针，其余按 Cut Map 展开。"

开场对齐可填模板见 `../templates/01-project-locks-and-probe.md` 顶部"开场对齐卡"；最小示例见 `../examples/feature-cookbook.md` C0。

## 1. 可跳转状态机 S0–S8（不是线性 1→8）

AI 创作允许故事先行、视觉先行、素材先行、边剪边生。进入后先判断当前在哪个状态，可在任意状态间跳转。

| 步骤（括号内是专业名） | 做什么 | 产物 |
|---|---|---|
| **第1步 · 开工对齐（S0 接案/上锁）** | 先做开场 Intake（第0节：回显/列路线/精准反问/术语说人话）；识别输入类型（剧本/梗概/参考图/已有素材/粗剪）；定"不能改/可商量/随便试"三类锁（第2节）；选入口：故事先行 or 视觉/素材先行 | 开场对齐卡、锁清单、入口判断 |
| **第2步 · 先试一条（S1 探针 Probe）** | 完整规划前，挑 1–3 个"做不出来全片垮"的最高风险点先做最小验证（第3节） | 试拍结论：能做/要改设计/换路线 |
| **第3步 · 捋故事节拍（S2 故事/Beat）** | 可由剧本顺推，也可由素材/粗剪**反推**节拍；只锁叙事任务与信息揭示顺序 | 节拍列表（可粗） |
| **第4步 · 列镜头蓝图（S3 Cut Map）** | 粗剪蓝图：要哪些镜、顺序、时长预算、节拍归属、必须镜 vs 可有可无、各镜口型级/花几分功夫；**不展开提示词** | 镜头蓝图（第4节） |
| **第5步 · 写镜头说明书（S4 Shot Contract）** | 只对"下一步真要生成的镜"展开镜头契约（第5节），按风险触发加载 reference | 镜头说明书 |
| **第6步 · 选做法（S5 生成路由）** | 先选控制方式与模型（第6节 Route 矩阵），再写提示词 | 做法决策 + 开场图资产 |
| **第7步 · 生成挑毛病（S6 生成 + 失败循环）** | 最小有效提示词生成；按两次/三次规则处理失败，记翻车记录 Failure Log（第7节） | 素材（带备选标记） |
| **第8步 · 先粗剪（S7 Rough Cut）** | 尽早粗剪，用真实素材验证节奏/叙事；暴露缺镜、冗镜、不通处，回第4/5步补删改 | 粗剪 + 补镜清单 |
| **第9步 · 精剪交付（S8 精剪/QC）** | 终剪、声画、调色、G6 质检、AI 披露、复盘回填 | 成片 + 复盘 |

**典型跳转**（S 编号即上表步骤）：素材先行 第1步→第2步→第7步→第8步→第3步（先有画面再倒推故事）；边剪边生 第8步↔第5步↔第7步循环；试拍失败回第1步/第4步改设计而非硬做。**任何时候发现素材推翻了规划，以素材为准回改镜头蓝图，不维护已经不成立的纸面分镜。** 全套术语人话对照见 `plain-language-glossary.md`。

## 2. Hard / Soft / Open 三类创作锁（S0 必做）

| 锁 | 含义 | 改动规则 |
|---|---|---|
| **Hard（硬锁）** | 既定台词/结局/事实、用户明确禁令、安全与平台红线、已锁定的主角身份资产 | 不可自行改；要改必须回到用户确认 |
| **Soft（软锁）** | 当前约定但可被证据推翻：镜头数、时长分配、景别、运镜、某场处理、BATCH 顺序、候选模型 | 可用生成/粗剪证据自行改，但要在 Failure/复盘里记录改了什么、为什么 |
| **Open（开放）** | 鼓励探索：开场形式、转场、VFX 细节、实验镜、节奏与声音处理 | 自由试，成了用、不成就回标准版 |

每个 Shot Contract / 决策标注它动的是哪类锁。探索期不要把 Open/Soft 当 Hard 锁死，否则会为一个本可放弃的镜头反复烧积分。

## 3. Probe 高风险探针（S1，完整规划前）

- 不是泛测平台的"测试片"，而是针对**本片具体的最高风险**做 1–3 个最小验证：没见过的视觉奇观、口型最重的一句台词、最难的跨镜连续性、平台未验证的能力（多人重叠对白、特定运镜、某 VFX）。
- 每个 Probe 只验证一个假设，用最便宜的方式（短时长、单镜、可丢弃）。
- 结论三选一：**能做**（进规划）／**要改设计**（换拍法/构图/口型级规避）／**换路线或删戏**（回 S0/S3）。
- Probe 通过前，不展开全片 Shot Contract，避免在不可行设计上写满一整本提示词。
- 用户明确跳过探针时，至少对"平台从未验证过的新能力"保留一次最小验证；已在同平台验证过的镜型可不重复探。

## 4. Cut Map（粗剪蓝图，先于逐镜提示词）

一张轻表/列表，回答"成片大概由哪些镜头按什么顺序组成"，字段从简：

`镜号 ｜ Beat/叙事任务 ｜ 预估时长 ｜ 必须镜 or Candidate ｜ 口型级(A+/A/B/C) ｜ 连续性级(L0–L3) ｜ 首选生成路线 ｜ 首帧资产 ｜ 备注`

- **必须镜**：拿掉故事就不成立；**Candidate（候选镜）**：增强但可被替换/删除/换序，去留交给粗剪。
- Cut Map 阶段不写摄影灯光色彩的完整提示词，只标影响可行性的关键点。
- 故事片可在 S2 后顺推 Cut Map；视觉先行可先生成素材，在 S7 用素材反填 Cut Map 与 Beat。
- Cut Map 是活的，粗剪后必改。

## 5. Shot Contract（镜头契约，只在生成该镜时展开）

替代"九列分镜 + 每镜七层"。**一个镜头一张契约，字段按风险增减，不为格式凑满**：

1. **镜号 / Beat / 叙事任务**：这镜不成立会丢什么信息或情绪（没有独立叙事任务的镜并入别镜）。
2. **首态 → 末态**：进入时人物/道具/光/声的状态；末态必须能接下一镜（动作相位、屏幕方向、持物、伤痕）。
3. **不可失败项（must-get，≤3 条，写进提示词最前面）**：本镜绝不能错的东西，如"周启正脸、口型对上'仅好友可见'、中间停顿 1 拍""右手持按钮、动作全片只发生一次"。
4. **生成路线 + 模型 + 首帧/参考资产**（第6节）。
5. **口型级 A+/A/B/C** 与 **连续性级 L0–L3**，以及必须继承的具体项。
6. **最小有效提示词**（第8节）：只展开会影响本镜成功的 2–4 个工艺层 + 台词（含语气语速/打断重叠规范）。
7. **可判定验收标准**：对照它判过/废/Candidate，不凭感觉。
8. **风险触发**：本镜哪类风险高，就去读对应 reference（第9节触发表），不高的不读不写。

## 6. Generation Route 生成路由矩阵（S5：先选控制方式，再写词）

连续失败时，先怀疑路线，而不是提示词不够长。

| 路线 | 适用 | 解决什么 |
|---|---|---|
| **T2V 文生视频** | 无可用参考、纯探索、空镜、蒙太奇、难用图锁定的画面 | 从零探索 |
| **I2V 首帧驱动**（主力） | 有角色定妆照/场景图；保脸、保景、保构图 | 身份与场景一致性 |
| **首尾帧 / 续写** | 跨镜动作接点、锁定末态、L3 连续性、动作切 | 相位衔接、不重演 |
| **V2V / 视频参考驱动** | 已有近似镜头，要改风格/动作/光线但保留构图与运动 | 借运动与构图 |
| **多图/角色参考** | 多人同框、角色+场景组合、多角度保同一人 | 多主体一致 |
| **先图生图合成首帧再 I2V** | 单图无法同时给角色和场景时，先把角色 P 进正确场景 | 复杂同框 |
| **画面与声音分轨** | 内嵌口型/多人重叠做不稳时，画面按节奏演、配音分轨后期对 | 规避口型风险 |
| **纯后期** | UI、计票数字、招牌、字幕、黑屏系统字 | 彻底规避乱码 |

选路线顺序：先看"这镜最不能错什么"（脸→I2V/多图；动作接点→首尾帧；已有满意运动要改→V2V；没参考→T2V；文字→后期）。模型选型（哪类镜用哪个模型）见 `ai-production-measurement.md` 的路由表，二者配合：**Route 决定控制方式，模型路由决定用哪个引擎**。

## 7. Failure Log 与两次/三次规则（S6，失败是循环核心）

每条失败记一行：`镜号｜路线/模型｜失败现象(对照 D1–D10)｜我的假设｜改了什么｜结果`。

- **第 1 次失败**：单变量改提示词（一次只改一处，对照 `ai-production-measurement.md` 缺陷对策表），不推翻路线。
- **第 2 次失败**：换策略——降单段负荷/拆 Shot、降口型级（用侧脸/反应镜规避）、降连续性投资、改 must-get 优先级。
- **第 3 次失败**：**换 Generation Route 或换模型**（如 T2V→首尾帧、内嵌→分轨）；仍不行则回 S3 Cut Map：删镜、并镜、换拍法、改戏。
- A+ 关键镜可放宽上限但有顶（如 5–6 条）；超过说明设计超出当前模型能力，改设计而不是无限重试。C 级镜"挑能用就过"。
- 熔断阈值、可用秒成本、缺陷 Pareto 见 `ai-production-measurement.md`。

## 8. 最小有效提示词（替代每镜七层全写）

- **顺序**：不可失败项前置（身份与首帧锚点 → 本镜唯一主事件 → 关键口型/末态）→ 只写影响本镜成败的 2–4 个工艺层（摄影/运镜/灯光/色彩/表演/材质/声音中挑相关的）→ 台词 → 本片真会翻车的少数负面词。
- **删除**：模型不响应的变量、本镜不可见的细节、为"显得专业"而堆的同义词、与主事件无关的 VFX/运镜。
- 一个 C 级空镜/群杂/UI 镜可以只有一两句话；一个 A+ 正脸长台词镜才值得展开表演/光色/口型多层。**层数由风险决定，不由模板决定。**
- 工艺术语仍须紧跟可见/可听结果（"伦勃朗光，近侧脸颊三角亮斑"），但只在该层影响成败时写。
- 台词规范（语气语速前置、标点承担节奏、抢话/打断/重叠标注、画内画外系统声分清）见 `ai-video-platform-production.md` 第4节。

> 只展开会影响**当前镜头/当前任务**成功的 reference；没有该风险就不读不写。下列为触发条件 → 加载项。

## 10. L0–L3 连续性投资等级（把重生成本花在观众会察觉处）

| 级 | 观众是否察觉 | 投入 |
|---|---|---|
| **L0** | 看不到：快切、背景、虚焦、会被剪掉、UI 后期 | 不投资，漂移不重生 |
| **L1** | 几乎不察觉：同场景同批、非相邻、远景群演 | 同批生成 + 首帧一致即可，小漂移接受 |
| **L2** | 会察觉：相邻镜、同角色连续对话、同场景光色 | 锁脸+服装+光向+末态相位，漂移要修 |
| **L3** | 一眼穿帮：主角跨场身份、关键道具/持物手别、动作接点、180° 轴线、关键伤痕/服装变化 | 严格：首尾帧/V2V/合成首帧，必要时多生成备选 |

定级问一句"**这个不连续，观众会看到吗？会影响理解吗？**"——不会就降一级，把积分让给 A+ 表演镜和 L3 接点。

## 11. 粗剪优先与素材反推（S7）

- 攒到一批"能用（含 Candidate）"的素材就尽早粗剪，哪怕带占位、无配音、无调色。真实节奏和纸面时间码几乎总会不同。
- 粗剪回答：故事讲清了吗？哪镜多余？哪里缺信息？节奏哪里塌？A+ 镜的表演成立吗？
- 据粗剪回 Cut Map：**补镜**（缺信息/缺反应/缺接点）、**删镜/并镜**（Candidate 不成立）、**改戏/改序**（素材给出了更好的可能）。Beat 可由素材反推，不执着原分镜。
- 终剪前可多轮 S7↔S4↔S6；越晚发现的缺镜成本越高，所以粗剪要早、要粗、要敢剪。

## 12. 单人导演的"工艺视角"（替代虚拟剧组会议）

不模拟多人剧组、不输出跨部门会议记录。需要时导演自己按几个视角各看一眼当前镜头即可：**表演**（身体可观察？刺激→反应成立？）、**摄影**（景别/机位/运镜有叙事理由？）、**灯光色彩**（光源有源？谁亮谁暗？跨镜匹配？）、**声音**（声源/主次/台词避让/静默）、**连续性**（末态接得上？）、**剪辑**（切点落在事件上？主事件只发生一次？）。每个视角只在它能改变这镜成败时介入。

## 13. 导演工艺保留项（能力不删，触发方式改变）

尊重既定剧情台词、事件驱动镜头与剪辑、动作因果/轴线/末态、表演可观察化、灯光色彩声音服务叙事、不把未知模型能力当事实、不用 VFX/慢动作/推镜套路代替判断、复杂度分级与拆 Shot——这些继续有效，从"全流程前置检查项"变为"被当前问题触发的工具"。
